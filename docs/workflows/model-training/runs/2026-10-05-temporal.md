# Temporal resolution experiment, 2026-10-05

## Hypothesis and protocol

Compare 30-second and 15-second windows against the frozen v0.4 model. A local physical change may be diluted in a minute aggregate. This is a hypothesis, not a diagnosis of the previous misses.

- Historical normal train and mixed validation only. Preserve v0.4 whole-run fit/early-stop/calibration/development assignments. Never use the six previously evaluated holdout batches for selection.
- Same class-specific AE/IF architecture, RobustScaler, top-four normalized residuals, 3,000 maximum AE updates/class, seed 20261005. All inputs remain generic semantic features. Both models are persisted; selected score remains AE-only.
- Use the intersection of minute grids completely tiled by both short-window representations. No imputation of absent windows. Report excluded coverage explicitly.
- Compare max score per common minute. Threshold is q99 of max scores in normal calibration minutes, with strict cutoff. Thus the number of opportunities per minute is calibrated instead of comparing unequal counts of 15-second and 60-second false windows.
- Report all original event intervals and the four declared physical families. Also report localization using the native short intervals; this prevents credit from a nearby alert elsewhere in the same minute.
- Selection fixed before scoring: more physical detections, no loss of total event detections, precision >=0.5, no increase of falsely alerted minutes, and at least baseline physical detection under native localization. Rank eligible candidates by physical detections, total detections, then false minutes.
- Generate a fresh independent holdout only if a candidate passes. Existing tests are already consumed. A failed experiment does not replace v0.4.

## Duration bug and compatibility

The parser accepted `30s` but returned one minute; it also truncated fractional minutes. It now preserves positive finite durations down to microsecond resolution. Window generation converts duration to integer microseconds before iteration. New training artifacts persist `window_duration_version: 2`; inference/evaluation preserve the historical interpretation for artifacts without the marker. Do not alter the marker on a previously trained model to change its window size.

Tests cover parsing, invalid durations, 30-second window boundaries/counts/slopes, training/scaling/save/load/inference and exposure, old artifact interpretation, and minute-grid alignment with missing, duplicate and overlapping subwindows.

## Results

Both temporal candidates failed the development gate. On the shared grid (2,057 development minutes, 124 events), v0.4 detects 53 events with 5 false minutes; 30s detects 55 with 27 false minutes; 15s detects 43 with 12 false minutes. Physical detections are 4/35, 5/35 and 4/35 respectively. Native localization reduces those short-window physical counts to 4/35 and 3/35. No independent test was consumed for these models; neither replaces v0.4.

Coverage reconciliation exposed an endpoint issue. The shared grid excludes 177 development minutes, all at record tails; they contained 10 of the 15 original v0.4 false alerts. This prompted a **separate** hypothesis, after the temporal screen: emit only windows closed by the observed per-asset timestamp watermark. It is a batch processing correction with reduced emitted coverage, not improved learned sensitivity.

## Follow-up endpoint policy, frozen before fresh test

Development, unchanged v0.4 weights/threshold: strict complete-tail policy retains 1,965/2,234 minutes, keeps 53/124 detected events and 4/35 physical detections, and reduces false minutes from 15 to 4. These results motivated a new freeze and new seeds 910521/22/23. Acceptance was fixed before generation: no loss of detected events or physical detections, fewer false minutes, explicit excluded coverage and all original event denominators.

The same clean Lab 0.6.0 checkout `718babb7772c3a21f0b87c403f628540cbce58db` generated 240 runs per seed, suite 0.2.0, four workers. Only the 36 test runs per batch were evaluated. Original data and checkpoints remain local. Public [numeric evidence](../../../results/temporal-and-tail-20261005.json) includes source hashes, protocol, frozen artifact hashes, counts and provenance.

New test: **108 runs, 84 events, 22 physical events**. Both policies detect **33/84 events and 2/22 physical events**. False minutes decrease **23 -> 8** and precision increases **69.3% -> 86.4%**. No event becomes unobservable in this sample. Four positive minutes are excluded, including one detected positive minute, without losing an event detection. Keep this distinction between window and event metrics.

Coverage: 1,631/1,856 original minute windows retained; 225 incomplete tails excluded. Raw observed span is 28.7492 asset-hours; emitted complete windows cover 27.1833 asset-hours. False alert minutes per observed asset-day, using the **same denominator** for both policies: **19.20 -> 6.68**. Rates using each emitted-window denominator are separately reported (17.84 -> 7.06). Neither rate measures alarm episodes. Paired whole-run bootstrap, 2,000 replicates: change in false-minute count IC95% **[-25, -6]**.

Decision: expose `--tail-policy complete` as an explicit batch option; retain v0.4 weights and default compatibility. The >=50% event target remains unmet (39.3% in this new test). Physical learning has not improved. PR-AUC is not used to claim improved ranking because removing tails changes the evaluated population.

## Checks and limits

**60 local tests passed**, including native subminute train/infer/evaluate, explicit CLI tail policy, compatibility and boundary handling. The independent evaluator checked that the implemented complete-window generator exactly matches the analytical cutoff for feature values and window labels; ambiguous legacy single-event-ID fields are excluded from this identity check, while event metrics use complete ground-truth intervals.

The running temporal experiment began before the duration-version compatibility marker was implemented. Its actual 15s/30s widths were verified from cached windows; the marker was then added to those research artifacts without changing weights, scales, thresholds or scores. They remain rejected research models. No public weights or release tag were produced.

An observed-data watermark cannot close windows during silence. A continuous monitor requires an external clock/watermark and missing-data policy to detect a terminal communication loss; that capability is not implemented by this batch option. Do not extrapolate the endpoint result to better physical fault detection or long-term plant alarm quality. All nine evaluated holdout seeds are now consumed; future selection needs another independent test.
