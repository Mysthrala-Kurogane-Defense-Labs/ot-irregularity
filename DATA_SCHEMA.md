# Data schema v1

Required long-format columns: `run_id`, `asset_id`, `timestamp`, `tag_id`, `signal_class`, `value`. Recommended columns: `asset_class`, `unit`, `quality` (`good`, `uncertain`, `bad` or null), `sampling_interval_ms`, `operating_regime`, `engineering_min`, `engineering_max`. Additional fields are allowed. `is_anomaly` (Boolean/0/1), `event_id`, and `event_start_us` (UTC epoch microseconds) are optional evaluation metadata. The trainer excludes these labels and identifiers from features. Product-specific identifiers are not required.

CSV and Parquet are supported; Parquet is recommended for large data. Timestamp must parse, values must be finite numeric, required fields cannot be null, and `(run_id, asset_id, timestamp, tag_id)` must be unique. `signal_class` is the generic semantic feature name used by the pipeline. Normalize vendor tags into this shared field before training.

Semantic normalization (`tag_id` to `signal_class`, engineering units, and source-quality interpretation) is separate from ML scaling. `normalization.canonical_units` converts supported compatible units before window generation and fails on missing, unknown, or dimensionally incompatible units. `RobustScaler` or `StandardScaler` is fit afterward and saved with the model. Signal statistics include `good`, `uncertain`, and ungraded observations, and exclude `bad`; this lets data without quality grades remain usable while retaining quality ratios as separate features.

Known contract gap: the current window builder assumes one measurement point per (`run_id`, `asset_id`, `signal_class`). If several points share a broad class (for example oil and discharge temperature), their samples are aggregated together. A normalized point role independent of vendor `tag_id` is needed to preserve those channels. Discrete/binary values should also carry an explicit value kind; the present feature builder treats numeric codes as continuous. Details and proposed compatibility path are in the [semantic feature audit](docs/FEATURE_SEMANTICS_AUDIT_OTLAB.md).

Dataset directories contain `train/`, `validation/`, optional `test/`, and optional `challenge/`. Train and validation split groups must be disjoint. Training reads only those first two partitions.

## Experimental telemetry-health cadence contract

The separate research health channel requires `declared_sampling_interval_ms`: a positive configured interval with source provenance, known during acquisition. It never derives that expectation from observed gaps. A genuine configuration change invalidates coverage/repetition for the affected run segment; split the run at a verified configuration boundary before subsequent use. Missing declarations remain unavailable.

Preserve observed elapsed intervals as `observed_sampling_interval_ms` when supplied. In OT Irregularity Lab, row-level `sampling_interval_ms` is an observed gap; configured cadence comes from run metadata and the scenario. `scripts/health_cadence.py` verifies those files and their manifest hashes before attaching the explicit declaration. Historical prepared rows are matched to their verified raw observations. This adapter correction is scoped to the health study; existing frozen AE/IF feature inputs and scores remain unchanged. Generic acquisition sources must document the meaning and provenance of their cadence fields rather than assuming the Lab convention.
