## Implementation findings and limits

- First training attempt correctly stopped because the Lab uses uppercase quality values (`GOOD/UNCERTAIN/BAD`) while the loader requires lowercase. The adapter now canonicalizes quality values; a regression test covers it.
- The Lab reuses local event IDs such as `evt-1` across runs. IDs are now namespaced by `run_id`; a metrics fix excludes null/NaN event IDs from event counts. Ground-truth event start times are preserved separately from the row/window where labels are anchored.
- A complete communication-loss interval may contain no observations. For evaluation only, the adapter marks the nearest surviving row so a containing feature window is scored against that ground-truth event. If the asset has no rows at all or the run cannot form a complete window, it remains unevaluable.
- Current model separation is poor: synthetic fault test ROC-AUC stays near 0.5, point recall is low, and normal-transition false-alarm rates remain high. The 1-minute ensemble is a useful next configuration to test, not a validated universal default. Do not tune against this single test set and then claim independent performance.
- Data and artifacts are outside Git under `$LOCAL_EXPERIMENTS\`. The software repo remains uncommitted. No source data or private/customer data was added to the project. The Lab repository was not modified by this work; its observed worktree/HEAD change is recorded above as unresolved concurrent workspace activity.
